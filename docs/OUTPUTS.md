# VictoriaMetrics, Home Assistant and recovery

The exporters send decoded measurements from `qiotld` or `qiotlctl watch`. Both outputs are disabled by default, and neither enables device acknowledgements. Exporters require `storage.path`; their network workers run independently of capture and protocol replies. Backfill and HA preview do not connect to device MQTT topics.

## Configuration

These sections can be placed in a separate YAML file and included or overlaid with `-c`. Credentials stay in the existing MQTT configuration; HA uses a separate client on the same broker. Profiles remain reusable **settings** profiles; HA identity belongs to the individual device.

```yaml
---
storage:
  path: ./captures/observations.sqlite
  capture_raw: true
  max_bytes: 10737418240 # 10 GiB soft limit; 0 disables the limit
outputs:
  victoriametrics:
    enabled: false
    import_endpoint: http://127.0.0.1:18428/api/v1/import
    metrics_prefix: qingping_iot_
    # username: metrics-writer
    # password_env: VM_PASSWORD  # or password_file, or password
    # ca_file: ./ca.pem
    insecure_skip_verify: false
    timeout: 5s
    batch_size: 1000
    flush_interval: 1s
    retry_max: 1m
    include_invalid_time: false
    normal_only: false
  home_assistant:
    enabled: false
    discovery_prefix: homeassistant
    state_prefix: qiotlctl
    birth_topic: homeassistant/status
    bridge_id: qiotlctl
    expire_after: 600s
```

`import_endpoint` is the full URL: `/api/v1/import` for single-node VM or vmagent; typically `/insert/0/prometheus/api/v1/import` for tenant 0 through vminsert. Query parameters are supported, but embedded URL credentials are rejected. Use `username`/`password` for basic authentication. TLS verifies certificates by default; `ca_file` extends the system trust roots. Redirects are not followed. Certificate/password paths resolve relative to their YAML file. Direct `QIOTLCTL_VM_PASSWORD` overrides a configured password source. `config show` redacts credentials and endpoint query values.

Global environment overrides are generated by `qiotlctl config env`: `QIOTLCTL_VM_ENABLED`, `QIOTLCTL_VM_IMPORT_ENDPOINT`, `QIOTLCTL_VM_METRICS_PREFIX`, `QIOTLCTL_VM_USERNAME`, `QIOTLCTL_VM_PASSWORD`, `QIOTLCTL_VM_PASSWORD_ENV`, `QIOTLCTL_VM_PASSWORD_FILE`, `QIOTLCTL_VM_CA_FILE`, `QIOTLCTL_VM_INSECURE_SKIP_VERIFY`, `QIOTLCTL_VM_TIMEOUT`, `QIOTLCTL_VM_BATCH_SIZE`, `QIOTLCTL_VM_FLUSH_INTERVAL`, `QIOTLCTL_VM_RETRY_MAX`, `QIOTLCTL_VM_INCLUDE_INVALID_TIME`, `QIOTLCTL_VM_NORMAL_ONLY`, and the corresponding `QIOTLCTL_HA_*` fields shown by that command. `QIOTLCTL_STORAGE_MAX_BYTES` controls the journal limit. Existing file/CLI/environment precedence is unchanged.

## Python VM compatibility

The contract matches [Python commit d4fa28a2, vm.py](https://github.com/danielskowronski/qingping-iot-mqtt/blob/d4fa28a2bd182227b2396c33a0e38f1e50d75631/src/qingping_iot_mqtt/cli/vm.py):

| Sensor | Default metric | Unit | Models |
|---|---|---|---|
| Temperature | `qingping_iot_temperature` | `°C` | CGP22C, CGDN1 |
| Humidity | `qingping_iot_humidity` | `%` | CGP22C, CGDN1 |
| CO2 | `qingping_iot_co2` | `ppm` | CGP22C, CGDN1 |
| Battery | `qingping_iot_battery` | `%` | CGP22C, CGDN1 |
| Wi-Fi signal | `qingping_iot_signal_strength` | `dBm` | CGP22C, CGDN1 |
| PM2.5 | `qingping_iot_pm25` | `µg/m³` | CGDN1 |
| PM10 | `qingping_iot_pm10` | `µg/m³` | CGDN1 |

Each series has exactly the Python labels: `device_mac` (uppercase, no colons), `device_name` (alias), `sensor`, `unit`, `device_model`, and `device_protocol` (`hex`/`json`). Known models filter unsupported sensors. Unknown models export understood numeric sensors; configure a MAC to retain conventional MAC identity, otherwise the configured device ID is used. Alias changes create new VM series, as in Python. No capture ID, arrival timestamp or quality status is added as a label.

The prefix gains a trailing underscore if nonempty; `metrics_prefix: ""` removes the prefix. Device timestamps are converted from seconds to milliseconds. JSON wire units/values are preserved for VM, including Fahrenheit or `C` when explicitly reported, while HA receives the normalized value/unit. Older Go captures stored without raw bytes or original values can only reproduce their stored normalized readings.

Python did not implement type-12 realtime readings. Go exports those as additional measurements using the same naming contract. Numeric sensor-error/status values are included by default, matching Python; `normal_only: true` excludes invalid sensor quality (valid high/low readings remain eligible).

Intentional differences from Python:

- Network calls are asynchronous and batched. Network/HTTP failures remain pending and retry with bounded exponential backoff and jitter, including persistent authentication errors. CLI drain/backfill stops on an error with durable progress; rerun it, or let the enabled daemon drain the queue.
- Missing/pre-2020/future timestamps are quarantined by default. Future means more than five minutes beyond original receive time, or current time for legacy decoded rows that lack receive time. `include_invalid_time: true` explicitly exports these timestamps unchanged. No timestamp is silently repaired; overflow/nonfinite values are never sent.
- Identical series/timestamp/value samples are deduplicated locally. The first accepted value wins when values conflict at the same series/timestamp; later conflicting values remain in `output_rejections`. Inspect them with `outputs rejections`.

VM's [JSON-line import API](https://docs.victoriametrics.com/victoriametrics/#how-to-import-data-in-json-line-format) accepts bounded batches. A 200/204 response is endpoint acceptance, not proof that every row was parsed or made crash-durable by the server. Validate imports through queries and the server's `vm_rows_invalid_total`. Backfill may also require a query-cache refresh on the VM side.

## HA identity and discovery

For a bedroom sensor, configure its HA identity as follows:

```yaml
---
devices:
  bedroom:
    mac: "001122334455"
    model: CGP22C
    home_assistant:
      id: bedroom
      # name: Qingping Bedroom # generated from id when omitted
      expire_after: 600s
      # Optional per-sensor override; 0 inherits the device/global value.
      sensor_expire_after:
        signal_strength: 20m
```

This produces `unique_id: qingping_bedroom_battery`, device identifier `qingping_001122334455`, name `Qingping Bedroom`, manufacturer `Qingping`, and model `CGP22C - CO2 & Temp & RH Monitor`. The MAC connection uses the configured device address. CGDN1 uses `CGDN1 - Air Monitor Lite v1`; CGP23W uses `CGP23W - Temp & RH Monitor`.

`home_assistant.id` uses lowercase letters, digits, underscores or hyphens. It defaults to the lowercase stable device ID and must be unique among HA-enabled devices. Set it explicitly to preserve existing entity IDs. Names default to `Qingping ` plus the humanized HA ID; `name` overrides capitalization/wording. `enabled: false` disables HA for one device. Renaming the CLI alias does not change HA unique IDs; changing the HA ID does.

The bedroom battery discovery topic is `homeassistant/sensor/qingping_bedroom/battery/config`. State is decoded JSON at `qiotlctl/<device-id>/battery/state`, such as:

```json
{"value":98,"timestamp":1792144800,"quality":"normal"}
```

Discovery uses `{{ value_json.value }}` rather than decoding the original device's HEX/JSON envelope. The existing raw `qingping/<mac>/up` topic is not modified. Default UTF-8 encoding applies. Discovery includes the device mapping, unit, appropriate device class, `state_class: measurement`, QoS 1, and expiry. Battery and signal strength are diagnostic entities. Generic models acquire discovery for understood HA-compatible sensors once observed.

Broker permissions must cover both clients: qiotld publishes discovery/state and
subscribes to HA's birth topic; HA subscribes to discovery/state and publishes its
birth/status. Device-topic access alone is insufficient. See the
[EMQX ACL requirements](DEPLOYMENT.md#mqtt-permissions-and-emqx-acls),
[copyable ACL example](../charts/qiotlctl/examples/emqx-acl.conf) and
[missing-discovery troubleshooting](DEPLOYMENT.md#troubleshooting-missing-home-assistant-discovery).

Before enabling discovery for entities already configured manually in HA, remove/disable the old manual definitions while preserving their unique IDs in this configuration. The same MQTT unique ID cannot represent two concurrently active definitions. Check HA entity and device registry associations after migrating manual definitions.

```sh
qiotlctl -c config.yaml ha preview --device bedroom > ha-preview.json
qiotlctl -c config.yaml ha cleanup                # preview obsolete owned discovery
qiotlctl -c config.yaml ha cleanup --publish      # explicitly publish those removals
qiotlctl -c config.yaml ha cleanup --all          # preview removal of all owned entities
```

Preview has no network or database writes. Cleanup only uses the journal's owned-discovery manifest for the configured broker/prefix/bridge; it does not scan or remove unrelated topics. Disable publishing or remove the relevant device before cleanup, otherwise the publisher may announce it again. `--sqlite` chooses a different manifest database. Cleanup removes discovery; retained availability messages can remain harmlessly under the state prefix. Changing broker/prefix/bridge requires using the old configuration to clean its old manifest.

## HA freshness and recovery

Discovery is retained; states are non-retained. The publisher subscribes to HA's configurable birth topic (default `homeassistant/status`) and refreshes discovery/current state after `online` or a broker reconnect. State is sent again after discovery to allow HA subscriptions to settle. MQTT QoS 1 confirms broker acceptance, not HA consumption.

HA keeps a separate persisted latest sample per sensor. Older batches and duplicates never replace newer values. Invalid-clock samples cannot poison this view. Invalid quality or incompatible units become unavailable/unknown, never zero. A heartbeat can update RSSI; it cannot refresh CO2 or temperature. Expiry is checked against measurement time, including after restarts, with a bridge last-will plus per-sensor availability. Republish does not reset the tool's freshness clock. The [HA sensor docs](https://www.home-assistant.io/integrations/sensor.mqtt/#expire_after) explain why retained state can incorrectly revive stale data.

The bridge advertises offline if capture/storage is not ready. Output failures do not change capture readiness or HA bridge availability. `/readyz` includes required enabled exporters; `/healthz` and `doctor --daemon-url` provide cached reasons. See [diagnostics](DIAGNOSTICS.md) for grace, endpoint probes and discovery readback permissions. Run one HA publisher for a broker/state-prefix/bridge-ID combination. Multiple writers are not coordinated; use distinct namespaces for independent instances. The HA integration exports sensors only, without settings/control entities.

## Historical backfill and recovery

Use a consistent SQLite snapshot. The old history file is never migrated or written. `auto` chooses Python `sensor_readings` if present, otherwise raw captures. `--source raw` decodes `raw_payloads` or a Go `captures` journal, including stored normalized events when raw recording was disabled.

```sh
# Preview eligible lines; no network, queue writes or checkpoints.
qiotlctl -c config.yaml backfill vm --sqlite /path/to/history.sqlite3 \
  --device bedroom,living-room,office --since 2026-01-01T00:00:00Z --until 2026-10-16T00:00:00Z \
  --dry-run > history.jsonl

# Import and persist progress. Repeating the same command resumes it.
qiotlctl -c config.yaml backfill vm --sqlite /path/to/history.sqlite3 \
  --job migration-2026 --state-db backfill-state.sqlite

# Optional: queue for later delivery instead of using HTTP now.
qiotlctl -c config.yaml backfill vm --sqlite /path/to/history.sqlite3 \
  --job migration-2026 --state-db backfill-state.sqlite --enqueue-only
qiotlctl -c config.yaml outputs --sqlite backfill-state.sqlite drain-vm
qiotlctl -c config.yaml outputs --sqlite backfill-state.sqlite status
qiotlctl -c config.yaml outputs --sqlite backfill-state.sqlite rejections --limit 100
```

`--since` is inclusive and `--until` exclusive **measurement time**; ordinary `replay` retains its receive-time filtering. `--after-id` starts after a source row ID; `--limit` bounds rows scanned in this invocation, including skipped rows. Resume can change the limit. `--type` is available only for raw-source filtering. Source rows with unmapped/disabled devices are counted as skipped. Malformed mapped input stops the job with its row ID; already committed pages remain queued.

Legacy decoded rows preserve their historical aliases, MACs, values and units; configured devices provide model/protocol. The raw path uses the selected Go decoder/model mapping and can therefore produce more readings than Python. Forensic time inclusion can be set with `QIOTLCTL_VM_INCLUDE_INVALID_TIME=true`; this is part of the job's mapping identity, so use a new job when changing it.

The queue and checkpoint commit together in pages of at most 500 source rows. Job identity binds the immutable source file/WAL metadata fingerprint (resolved path, size and modification time), source kind, bounds, selected devices, mapping, destination and relevant export policies. Changed snapshots/settings require a new job. CLI interruption or HTTP failure does not erase pending work. A resumed CLI first continues queueing and drains pending samples; `outputs drain-vm` can deliver independently. Live samples have priority over backfill in a shared queue. Backfill never updates HA or sends device replies.

Successful VM delivery compacts the row to a deduplication fingerprint/value/timestamp; its full payload is released. Captures and rejected evidence remain. A crash between remote acceptance and local checkpoint commit may retransmit the same sample: delivery is at least once, not exactly once. Destination changes leave old pending work intact; `outputs status` lists all target fingerprints and identifies the currently configured target. Restore the matching endpoint/prefix to drain old work.

| Outage | Recovery |
|---|---|
| VM down or authentication rejected | Record locally; retry independently. CLI returns an error and can resume. |
| HA restart | Reannounce discovery and only current, still-fresh state. |
| MQTT unavailable | Reconnect and resubscribe. Export captured VM backlog independently. |
| Process restart | Reopen queue and current-state database; resume delivery without resetting freshness. |
| Storage limit/failure | Stop ingestion rather than silently discard data; readiness fails. Pending rows remain. |

Messages missed before durable capture depend on broker/device retransmission. MQTT transport ACKs are distinct from device application ACKs; QoS 0 and firmware buffer limits prevent a blanket losslessness guarantee. Automatic device replies remain off by default. When enabled, history capture plus output enqueue commit before the application ACK.

## Retention and operational visibility

The 10 GiB default soft limit covers database/WAL/SHM usage, subtracting reusable free pages when checking capacity. A single bounded transaction can cross the limit; the following capture/page fails. Set capacity to suit a months-long archive, including compact deduplication rows and the raw capture journal. Zero explicitly disables the limit.

There is no automatic deletion of raw captures, pending work or rejected samples. `outputs prune-vm --before <RFC3339>` removes only **delivered** VM rows before that delivery time; it also removes their deduplication history. Replaying those samples afterwards can resend them. SQLite reuses freed pages; large pruning/compaction is best done with the writer stopped. Raw-journal rotation is explicit: drain pending work, preserve/archive the journal, then configure a new path. Never delete a journal with pending deliveries.

`outputs status` exposes pending counts, oldest enqueue time, job progress and sanitized delivery errors. `/metrics` adds `qiotl_vm_pending_samples`, `qiotl_vm_oldest_pending_seconds`, `qiotl_vm_samples_delivered_total`, `qiotl_vm_errors_total`, `qiotl_vm_healthy`, `qiotl_ha_publications_total`, `qiotl_ha_errors_total`, `qiotl_ha_healthy`, `qiotl_output_rejections`, and `qiotl_storage_bytes`. Counters reset on process restart; queue counts come from durable storage. Disabled exporter health gauges are not a readiness assertion. The endpoint contains operational metrics, not duplicate latest-value sensor gauges.

## Local VM development

```sh
docker compose -p qiotlctl-dev -f compose.dev.yaml up -d
# HTTP: http://127.0.0.1:18428 ; import endpoint: /api/v1/import
docker compose -p qiotlctl-dev -f compose.dev.yaml stop
```

The pinned VM v1.154.0 container binds loopback only, retains 18 months, and uses a separate named volume. It enables 1 ms deduplication, preserving distinct measurement timestamps while collapsing exact retransmissions. Query `/api/v1/export` to compare actual labels/values/timestamps, and inspect server invalid-row metrics. See [testing guide](VALIDATION.md).
